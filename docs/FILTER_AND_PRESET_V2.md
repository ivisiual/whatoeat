# 饭饭搭子：筛选与快捷方案 V2

## 核心判断

当前“用餐方式”不能继续作为全日唯一值。用户选了外卖，真实含义通常是“某一餐想点外卖”，而不是早餐、午餐、晚餐全部外卖。

正确的数据结构是“全局约束 + 三餐计划 + 软偏好”：

```js
settings = {
  global: {
    scene: "office",
    goal: "light",
    dailyBudget: "50to80",
    calorieTarget: 1600,
    allergies: ["nuts"],
    avoidIngredients: ["cilantro"],
    cuisineIds: ["cantonese", "jiangxi"],
    cuisineMode: "soft"
  },
  meals: {
    breakfast: {
      channelsAllowed: ["convenience", "canteen"],
      budgetMax: 15,
      timeMax: 10,
      hunger: "normal"
    },
    lunch: {
      channelsAllowed: ["canteen", "takeout"],
      budgetMax: 30,
      timeMax: 25,
      hunger: "starving"
    },
    dinner: {
      channelsAllowed: ["home_cook", "takeout"],
      budgetMax: 30,
      timeMax: 35,
      hunger: "normal"
    }
  }
};
```

`channelsAllowed` 是候选集合。引擎为每餐先选择一种渠道，再选择与该渠道匹配的菜，卡片展示最终渠道。不要把同一道菜的 `channels[0]` 当成结果渠道。

## 第一屏：只放快捷方案

顶部问题改成“今天怎么过？”，用 6 个可横向滑动的小卡片：

| 快捷方案 | 早餐 | 午餐 | 晚餐 | 适合谁 |
| --- | --- | --- | --- | --- |
| 工作日通勤 | 便利店 / 早餐铺 | 食堂 / 外卖 | 自己做 / 外卖 | 普通上班日 |
| 加班续命 | 便利店 | 食堂 | 外卖 | 晚归、不想开火 |
| 控卡工作日 | 便利店 / 自制 | 食堂轻食 | 自制 | 减脂用户 |
| 健身训练日 | 高蛋白早餐 | 食堂 | 高蛋白自制 | 训练后恢复 |
| 居家做饭 | 自制 | 自制 | 自制 | 周末或远程办公 |
| 懒得动 | 便利店 | 外卖 | 外卖 | 真正想少做决定 |

点击快捷方案后，不直接封死筛选，而是生成一份可编辑的三餐计划摘要：

> 早餐便利店 · 午餐食堂/外卖 · 晚餐自己做

摘要下方只保留一个“细调三餐”按钮。多数人一步生成，想认真选的人再展开。

## 展开态：三餐独立编辑器

桌面端是三列，手机端是三个折叠卡片。每张卡只显示与该餐相关的选项：

- 渠道：食堂、外卖、便利店/早餐铺、自己做。
- 预算：早餐 `≤10 / ≤15 / 15+`，午晚餐 `≤20 / ≤30 / 30+`。
- 时间：早餐 `5 / 10 / 20 分钟`，午餐 `15 / 30 / 45 分钟`，晚餐分“等外卖”和“下厨时间”。
- 胃口：垫一口、正常、很饿。
- 餐型：饭、粉面、汤粥、沙拉/轻食、小吃拼盘。
- 当餐目标：清爽、顶饱、高蛋白、蔬菜多。

“厨具”只在该餐包含“自己做”时出现；“外卖等待时间”只在包含“外卖”时出现。不要留空白占位。

## 全局详细筛选

详细筛选建议分组，不要一次铺满：

1. **身体与安全（硬条件）**：过敏、宗教/伦理饮食、不吃牛/猪/海鲜/蛋/奶/坚果、辣度上限。
2. **今日目标（软偏好）**：控卡、高蛋白、吃轻一点、特别下饭、暖胃。
3. **地方口味（默认软偏好）**：粤、赣、湘、川、鲁、闽、苏、浙、徽、鄂、黔、桂、陕、新疆、东北、本帮。
4. **口感与温度（软偏好）**：热乎、凉爽、有汤、干香、酥脆、软糯。
5. **现实条件**：几个人、是否能加热、是否有冰箱、厨具、是否想利用剩菜、全天预算。
6. **推荐个性**：最近吃过的不出现、熟悉菜/探索菜滑杆、同一主蛋白一天最多出现一次。

菜系多选语义必须是 OR，例如选“粤菜 + 赣菜”表示两者都可，不是要求一道菜同时属于两个菜系。默认只是加权偏好；另给一个“只看所选菜系”的严格开关。

## 硬条件与软偏好

推荐失败时只自动放宽软偏好：口味、菜系、胃口、等待时间、探索度。以下条件绝不自动放宽：

- 过敏与忌口。
- 蛋奶素/纯素等饮食边界。
- 用户明确选择的唯一渠道。
- 预算硬上限（除非用户主动确认）。

无结果提示要写清楚放宽了什么，例如：

> 严格匹配只有 1 道菜；已把“湘菜”从必须改为优先，忌口保持不变。

## 生成算法

1. 读取快捷方案并得到三餐的 `channelsAllowed`。
2. 对每餐分别执行硬筛选。
3. 对剩余候选按菜系、目标、口味、时间、历史新鲜度打分。
4. 在同一天内加入组合惩罚：相同菜、相同主食、相同主蛋白、相同渠道连续出现都扣分。
5. 加入最近 7 天惩罚；当候选足够时，最近 3 天吃过的菜直接排除。
6. 进行加权随机，而非总取最高分；保存本次已使用的菜 ID。
7. 候选总权重为 0 时重新构建未使用池，不能回退到可能重复的旧池。

建议组合分：

```text
单菜得分 = 基础分
         + 菜系命中 18
         + 目标命中 14
         + 口味命中 8
         + 渠道契合 12
         + 新菜探索 0~10
         - 近 7 天出现 8~35
         - 今日同主蛋白 20
         - 今日同主食 14
         - 今日同渠道 6
```

## 菜系选择器

手机端不要展示 16 个常驻胶囊。推荐结构：

- 首行：不限、粤菜、湘菜、川菜、赣菜、更多。
- 点击“更多”打开底部抽屉，支持搜索和“热门 / 八大菜系 / 地方风味”分组。
- 已选菜系回到首行显示为可删除标签。
- 每个菜系可以有一句弱提示，例如“粤菜 · 清鲜蒸炖”“赣菜 · 鲜辣咸香”。

## 手机布局

- 主容器宽度 `min(1180px, calc(100% - 32px))`；小于 640px 改为 `calc(100% - 24px)`。
- 页面左右留白最少 12px，任何筛选项不得导致横向滚动。
- 快捷方案横向滚动并提供局部露出，提示还能继续滑。
- 三餐结果在手机端为单列卡片；主要按钮固定在底部安全区上方，但不能遮住内容。
- 触控目标最小 44px；胶囊间距至少 8px。
- 细调面板使用折叠/底部抽屉，避免首屏出现“筛选墙”。
- 使用 `clamp()` 控制标题、间距和卡片内边距，不为每个手机宽度写一套固定像素。

## 验收场景

至少自动跑这些组合并检查 100 次生成：

1. 公司 + 工作日通勤：不能默认三餐全外卖。
2. 公司 + 加班续命：早餐便利店、午餐食堂、晚餐外卖均有结果。
3. 减脂 + 高蛋白 + 不吃牛肉：硬忌口始终有效。
4. 蛋奶素：任何“综合、套餐、拼盘、自选”都不能在成分不明时混入。
5. 粤菜 + 自己做：卡片有可访问的 GitHub 菜谱链接。
6. 赣菜 + 外卖：可推荐官方名单中的菜，但不显示虚假的 GitHub 菜谱按钮。
7. 赣菜 + 自己做 + 严格菜系：明确提示菜谱仍在补充，而不是静默给出别的菜系。
8. 连续点击 20 次：同一组三餐不连续出现；单次菜单三餐不重复。
9. 刷新页面：当天菜单和筛选恢复；跨日不把旧菜单标为“今日菜单”。
10. 375px、390px、768px、1440px：无横向滚动、按钮无遮挡。
